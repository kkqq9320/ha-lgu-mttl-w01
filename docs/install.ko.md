# 설치 안내

[English](install.md)

이 안내의 주소는 예시다. `192.0.2.10` 자리에는 자기 Home Assistant 기기의 주소를 쓴다.

## 앱 설치

1. 앱 저장소를 추가한다. [이 링크](https://my.home-assistant.io/redirect/supervisor_add_addon_repository/?repository_url=https%3A%2F%2Fgithub.com%2Fkkqq9320%2Fha-apps)를 열거나, **설정(Settings) → 앱(Apps) → 앱 설치(Install app)**에서 **⋮** 메뉴의 **저장소(Repositories)**를 골라 `https://github.com/kkqq9320/ha-apps`를 추가한다.
2. 앱 스토어에서 **LG U+ Multitap (MTTL-W01)**을 찾아 설치한다.
3. 앱의 **정보(Info)** 탭에서 **Watchdog**을 켠다. 상태 검사가 실패하면 Home Assistant가 앱을 다시 시작한다. **사이드바에 표시(Show in sidebar)**도 켠다.
4. **시작(Start)**을 누른다. 앱의 **로그(Log)** 탭에 멀티탭이 접속할 주소가 `[run] host_ip 192.0.2.10 (auto-detected from Supervisor)`처럼 나온다. 멀티탭이 이 주소에 닿지 않으면 **구성(Configuration)** 탭에서 `host_ip`를 넣고([옵션](../mttl_w01/DOCS.md#옵션)) 앱을 다시 시작한다.
5. 사이드바에서 **MTTL-W01**을 연다. 이 사이드바 메뉴는 Home Assistant 관리자에게 보인다. 앱 화면의 **웹 UI 열기(Open web UI)**도 같은 화면을 연다.

같은 화면이 Home Assistant 기기의 18282 포트에서도 열린다(예: `http://192.0.2.10:18282`). 같은 네트워크의 휴대폰과 다른 컴퓨터는 이 주소를 쓴다. 이 주소에서는 보기와 내려받기만 된다. [접근과 화면 잠금](#접근과-화면-잠금)을 본다.

### MQTT

Mosquitto broker 앱이 설치되어 있으면 앱이 시작할 때 그 접속 정보를 백엔드에 넘기고, 멀티탭이 MQTT 자동 등록(discovery)으로 Home Assistant에 나타난다. 브로커가 없으면 MQTT 없이 시작한다. 대시보드의 **Home Assistant MQTT** 카드가 연결 상태를 보인다. 나중에 브로커 설정을 바꾸는 방법은 [MQTT가 연결되지 않을 때](#mqtt가-연결되지-않을-때)에 있다.

## 접근과 화면 잠금

앱에는 로그인이 없다. 변경은 Home Assistant 사이드바에서만 받는다.

- **사이드바.** 콘센트 켜기·끄기, 이름 바꾸기, 잠금(child lock), 설정 페이지와 기기 창의 모든 설정은 사이드바의 **MTTL-W01**이나 앱 화면의 **웹 UI 열기(Open web UI)**로 연 화면에서만 된다. 이 화면은 Home Assistant 로그인이 보호한다. 백엔드는 Home Assistant Supervisor를 거치지 않은 변경 요청(POST, PUT)을 모두 403(`changes are only accepted through the Home Assistant sidebar`)으로 거절한다.
- **18282 포트.** `http://192.0.2.10:18282`는 보기와 내려받기용이다. 이 주소의 대시보드는 **Unlock** 자리에 **VIEW ONLY**를 보이고, 로그 화면에는 **버퍼 지우기**가 없다. 설정 페이지, 기기 창, **HIDDEN DEVICES**는 이 주소에서 값만 보이고 입력과 버튼은 모두 꺼진다. 펌웨어 파일과 Lovelace 카드 내려받기만 된다. QR 코드로 받는 APK, PC 도구의 접속 확인, Home Assistant 기기 페이지의 멀티탭 링크는 읽기만 하므로 이 포트에서 그대로 된다.
- **화면 잠금.** 사이드바의 대시보드는 열 때마다 잠긴 상태로 시작한다. 위쪽 막대의 **Unlock**을 누르면 콘센트 켜기·끄기, 이름 바꾸기, 잠금 설정, 새로고침, 기기 숨기기, 기기 설정 변경, 숨긴 기기 다시 표시·삭제를 할 수 있고, **Lock**을 누르면 다시 잠긴다. **DEVICE SETTINGS**는 잠긴 상태에서도 열리고, 창 안의 변경만 **Unlock**이 필요하다. 화면 잠금은 실수로 누르는 것을 막는 장치이고 보안 장치는 아니다. 설정 페이지에는 화면 잠금이 없다.
- **요청 헤더.** 변경 요청에는 `X-MTTL-Request: 1` 헤더도 있어야 한다. 다른 사이트의 웹 페이지는 이 헤더를 붙여 보낼 수 없다. 대시보드, 로그 화면, 설정 페이지는 이 헤더를 붙인다.

남는 위험: 같은 네트워크에서 18282 포트에 닿는 사람은 누구나 기기 목록, 전력 값, 로그를 읽고 APK, PC 도구, 펌웨어 파일을 내려받을 수 있다. 이 응답에는 암호가 없다. 10086, 18282, 49217 포트는 집 네트워크 밖으로 열지 않는다.

투오의 문서([docs/tuo](tuo/README.md), [mttl_w01/backend/README.md](../mttl_w01/backend/README.md))는 관리자 로그인과 투오의 웹 화면이 있는 투오 standalone 배포를 설명한다. 이 앱은 그 로그인을 없애고, 그 화면을 이 앱의 대시보드와 설정 페이지로 바꾸고, 위 규칙을 따른다.

## 멀티탭 준비

멀티탭마다 투오 펌웨어 1.0.111과 Home Assistant 주소가 필요하다. 둘 다 투오 PC 도구로 넣는다. 도구가 PC에서 펌웨어를 만들어 멀티탭의 설정용 Wi-Fi로 설치하고, 집 Wi-Fi와 Home Assistant 주소를 멀티탭에 저장한다. 멀티탭은 한 대씩 진행한다. 펌웨어 판과 도구의 자세한 내용은 투오의 [펌웨어 문서](tuo/docs/FIRMWARE_AND_PROVISIONING.md)(영어)에 있다.

### 준비물

- PC 도구: 대시보드의 **PC 도구 내려받기**로 받아 압축을 푼다.
- Wi-Fi가 있고 Python 3이 설치된 PC. 도구는 Windows, macOS, Linux에서 동작한다.
- 처음 실행할 때 PC의 인터넷 연결. 도구가 제조사 펌웨어 1.0.105를 내려받아 SHA-256을 확인하고 도구 폴더에 둔다. 내려받기에 실패하면 펌웨어 1.0.105나 LG U+ 1.0.66의 원본 파일(`.fwr`)을 도구 폴더에 넣는다.
- PC의 TCP 80 포트가 비어 있어야 한다. 도구가 이 포트로 펌웨어를 내보낸다. Windows에서는 관리자 권한으로 실행하고(임시 방화벽 규칙도 이때 더한다), macOS와 Linux에서는 `sudo`로 실행한다.
- 멀티탭이 붙을 2.4GHz, WPA2 보안의 Wi-Fi. 네트워크 이름은 32바이트까지이고, 이름과 암호 모두 `:`를 쓸 수 없다.
- 멀티탭이 접속할 Home Assistant 주소: 앱 로그의 `host_ip`([앱 설치](#앱-설치)의 4단계).

### 설정 모드로 바꾸기

전원 버튼을 주황 LED가 빠르게 깜빡일 때까지 약 10초 누른다. 그러면 멀티탭이 `TONLY_TAP_` 뒤에 짧은 부호가 붙은 이름의 Wi-Fi를 연다. 암호는 `LGU_` 뒤에 같은 부호를 붙인 것이다. 도구가 이 네트워크를 찾아 PC를 연결한다. 연결하지 못하면 직접 `TONLY_TAP_…`에 연결하고 Enter를 누르라고 안내한다.

### PC 도구 실행

펌웨어 설치와 주소 저장을 따로 실행하고, 그 사이에 멀티탭을 설정 모드로 둔 채 2분 이상 기다린다.

1. 도구 폴더(`mttl_setup.py`가 있는 폴더)에서 관리자 권한 터미널을 열고 펌웨어만 설치한다.

   ```text
   python mttl_setup.py ota --version 111
   ```

   도구가 펌웨어 1.0.111을 만들어 SHA-256을 확인하고, PC를 멀티탭의 `TONLY_TAP_…` 네트워크에 연결한 뒤 PC의 TCP 80 포트로 펌웨어를 보낸다. 멀티탭은 다시 켜진 뒤 설정 모드로 돌아온다.
2. 멀티탭의 전원을 그대로 두고 2분 이상 기다린다. 그동안 버튼을 누르지 않는다.
3. PC가 `TONLY_TAP_…`에 연결되어 있는지 확인한다. 멀티탭이 다시 켜질 때 연결이 끊기고 저절로 다시 붙지 않을 수 있다. 그다음 주소를 저장한다.

   ```text
   python mttl_setup.py provision-up
   ```

   도구가 Home Assistant 주소(`Backend IPv4`)와 집 Wi-Fi 이름·암호를 묻고 멀티탭에 저장한 뒤, 멀티탭이 `http://<Home Assistant 주소>:18282/api/devices`에 온라인으로 나타나기를 기다린다.

대부분의 macOS와 Linux처럼 Python 3의 이름이 `python3`이면 `python` 대신 `python3`을 쓴다. Windows에서는 `OTA_WINDOWS.bat`이 1단계를 실행하고 관리자 권한도 스스로 요청하며, `PROVISION_UP_WINDOWS.bat`이 3단계를 실행한다. 도구는 실행할 때마다 `logs` 폴더에 기록을 남긴다.

`python mttl_setup.py install --version 111`은 두 단계를 한 번에 실행하지만, 펌웨어를 보내고 약 10초 뒤 주소를 저장한다. 펌웨어 1.0.66이던 멀티탭 한 대에서 이 방법으로 설치했더니 새 펌웨어가 집 Wi-Fi에 붙은 채 처음 켜지고 30~40초 만에 다시 켜지며 1.0.66으로 돌아갔다. 위 순서로 설치했을 때는 1.0.111이 전원을 다시 켠 뒤에도 남았다(2026-10-13 확인).

`provision-up`이 온라인 확인을 끝내지 못하고 끝나도, 멀티탭이 잠시 뒤 대시보드에 나타날 수 있다. 나타나지 않으면 멀티탭을 다시 설정 모드로 바꾸고 `provision-up`을 다시 실행한다. 펌웨어는 다시 설치하지 않는다.

### 결과 확인

PC 도구는 멀티탭이 온라인이 되는지만 확인하고 펌웨어 판은 확인하지 않는다. 대시보드의 멀티탭 카드에서 이름 아래 줄에 MAC 주소와 `FW 1.0.111`이 나오는지 보고, 몇 분 뒤에도 그대로인지 본다. `FW 1.0.66`으로 바뀌었으면 펌웨어가 자리 잡지 못한 것이므로 [PC 도구 실행](#pc-도구-실행)을 처음부터 다시 한다.

## 펌웨어 되돌리기

멀티탭이 아직 설정 모드로 들어가면, PC 도구로 투오의 다른 두 펌웨어 프로필을 같은 방법으로 설치할 수 있다.

```text
python mttl_setup.py install --version 110
python mttl_setup.py install --version 66
```

1.0.110은 잠금(child lock)이 없는 투오의 로컬 백엔드용 펌웨어이고, 1.0.66은 LG U+ 순정 호환 펌웨어다. 이 판의 멀티탭은 TCP 80 포트로만 펌웨어를 받는데 앱은 이 포트를 열지 않으므로, 1.0.111로 돌아갈 때도 [PC 도구 실행](#pc-도구-실행)의 순서를 따른다.

## 설정 페이지와 기기 창

전체 멀티탭에 적용되는 설정은 설정 페이지에, 멀티탭 한 대의 설정은 그 멀티탭의 기기 창에 있다. 둘 다 사이드바에서만 변경을 받는다. 화면 잠금이 무엇을 막는지는 [접근과 화면 잠금](#접근과-화면-잠금)에 있다. 이 안내는 한국어 화면의 이름을 적는다. 위쪽 막대의 **EN**/**KR**로 언어를 바꾸며, 카드와 창의 제목은 두 언어 모두 영어다.

- 위쪽 막대의 **SETTINGS**가 설정 페이지를 연다. 카드는 **FIRMWARE**(목표 펌웨어와 OTA server), **FIRMWARE FILES**, **FIRMWARE JOBS**, **POLLING**(소비전력과 상태를 읽는 주기), **HOME ASSISTANT MQTT**(브로커, 보고 기준, Discovery 다시 보내기, Lovelace 카드)이다. 대시보드의 **펌웨어**와 **Home Assistant MQTT** 카드에 있는 **설정 열기**는 설정 페이지의 해당 카드로 바로 간다. 펌웨어 업데이트처럼 영향이 오래 남는 동작은 버튼을 한 번 더 눌러야 실행된다.
- 멀티탭 카드의 **DEVICE SETTINGS**가 그 멀티탭의 기기 창을 연다. 창에는 펌웨어 업데이트(펌웨어 1.0.111 미만이면 업데이트 버튼이 꺼지고 PC 도구를 안내한다. [펌웨어 되돌리기](#펌웨어-되돌리기) 참조), **MEASUREMENT**(전압, RSSI, 측정 주기), **CHILD LOCK**(멀티탭에서 상태를 다시 읽는다. 펌웨어 1.0.111만)이 있다.
- **HIDE DEVICE**로 기기를 숨기면 대시보드 맨 아래에 **HIDDEN DEVICES (N)** 구역이 나타난다. **다시 표시**는 기기가 보존한 이름과 누적 사용량을 그대로 두고 기기를 되돌린다. **기록 완전 삭제**는 그 데이터를 완전히 지운다. 버튼을 한 번 더 누르고 `DELETE`를 입력한 뒤 **완전 삭제**를 눌러야 실행된다.

## 문제 해결

### Home Assistant 주소가 바뀌었을 때

멀티탭은 접속할 Home Assistant 주소를 저장해 둔다. 주소가 바뀌면 다음을 한다.

1. 앱을 다시 시작한다. `host_ip`를 비워 두었으면 앱이 새 주소를 찾고, 넣어 두었으면 `host_ip`를 고친다.
2. [앱에서 펌웨어 교체가 시작되지 않을 때](#앱에서-펌웨어-교체가-시작되지-않을-때)에 따라 펌웨어 내려받기 주소를 바꾼다.
3. 멀티탭마다 [설정 모드](#설정-모드로-바꾸기)로 바꾸고 `python mttl_setup.py provision-up`(Windows는 `PROVISION_UP_WINDOWS.bat`)을 실행해 새 주소를 넣는다. 펌웨어는 다시 설치하지 않는다.

공유기에서 Home Assistant 기기에 고정 주소(DHCP 예약)를 주면 주소가 바뀌지 않는다.

### 앱에서 펌웨어 교체가 시작되지 않을 때

멀티탭은 대시보드 **펌웨어** 카드의 **OTA server** 주소에서 펌웨어를 받는다. 백엔드는 이 주소를 처음 시작할 때만 `host_ip`에서 가져오고 그 뒤로는 저장한 값을 쓴다. 바꾸려면 **SETTINGS**를 눌러 [설정 페이지](#설정-페이지와-기기-창)를 열고 **FIRMWARE** 카드의 **OTA server IPv4**에 주소를 넣은 뒤 **저장**을 누른다.

펌웨어 1.0.110이나 1.0.66의 멀티탭은 앱에서 교체할 수 없다. 기기 창의 업데이트 버튼은 꺼져 있고, 설정 페이지에서 **모두 순차 업데이트**를 눌렀을 때의 확인 목록은 이 멀티탭에 "실패 예정, PC 도구 필요"를 표시한다. [펌웨어 되돌리기](#펌웨어-되돌리기)를 본다.

### MQTT가 연결되지 않을 때

백엔드는 브로커를 찾은 첫 시작 때 Mosquitto 접속 정보를 한 번 저장하고, 그 뒤로는 저장한 설정을 쓴다.

- 이 앱보다 Mosquitto broker 앱을 나중에 설치했으면 이 앱을 다시 시작한다. 설정 페이지에서 MQTT 설정을 저장한 적이 없을 때만 된다.
- 다른 브로커 설정을 쓰려면 **SETTINGS**를 눌러 [설정 페이지](#설정-페이지와-기기-창)를 열고 **HOME ASSISTANT MQTT** 카드에서 **Home Assistant 연동 사용**을 켜고 브로커 주소(Mosquitto broker 앱은 `core-mosquitto`), 포트, 사용자 이름(**MQTT ID**), 암호를 넣은 뒤 **저장**을 누른다. **연결 시험**은 입력한 값으로 연결을 시험한다.
